# 运行中 Agent 识别与接入

适用范围：2026-10-03 基于官方 v4.2.1（`f4cb620`）构建的本地增强版。此功能尚未向上游发布。Windows x64 便携包可复制到其他 Windows 设备；macOS/Linux 未做实机验证。

## 使用步骤

1. 在目标设备启动需要联动的 Agent，再启动桌宠。
2. 右键桌宠 →「Agent 联动」→「识别运行中的 Agent…」。按名称或路径筛选，选择对应程序。改名的程序也会列出；同一 Node/Bun/Electron 等运行时的不同进程分别显示 PID。
3. 如果找到唯一兼容数据源，窗口会填入它。核对来源后点击「添加并启用联动」，立即生效，无需重启桌宠。
4. 如果没有找到，手动选择数据来源，或保留默认 JSONL 路径并添加联动，再点击「导出 OpenCode 插件…」。将生成的 `dsh-pet-bridge.js` 放入该 Agent 支持的插件目录，重启 Agent 后发送一项任务。

OpenCode 的标准项目插件目录是 `.opencode/plugins/`，用户插件目录是 `~/.config/opencode/plugins/`。二次开发程序可能改变插件加载方式，应以该程序的说明为准。导出时由用户选择文件位置，桌宠不会自动改写 Agent 配置。插件目录规则来自 [OpenCode 官方文档](https://opencode.ai/docs/plugins/)。

## 三种数据来源

| 方式 | 适用条件 | 不满足时 |
|---|---|---|
| Codex 会话事件 | 本机 Codex Desktop/CLI 保存标准 `CODEX_HOME/sessions` 会话记录；通常是 `~/.codex/sessions` | 远程执行、禁用会话保存或改变事件结构的分支需要另行适配 |
| OpenCode 兼容数据库 | 已有 SQLite 数据库，包含 `event` 表及 `type`、`data` 列，事件格式兼容原有 OpenCode 监视器 | 窗口会提示缺少兼容事件表，改用 JSONL 或分支自己的事件导出 |
| 通用事件文件（JSONL） | Agent 能写入工作/结束等任务事件；OpenCode 分支保留标准插件事件接口时可使用导出插件 | 没有事件、插件或 hook 接口的程序需要其开发者添加适配 |

程序正在运行与任务正在执行是两件事。识别窗口提供程序选择和数据源查找；宠物的工作动画、结束提醒由实际任务事件触发。不会根据进程名、CPU 占用或窗口标题假装联动成功。

数据库和已存在的事件文件均增量监听，启动时跳过历史内容。JSONL 路径可以先绑定，等待插件创建文件。插件只记录时间、Agent 标识、状态、工具名和会话标识，不记录提示词、工具参数、API Key 或代码内容；文件超过约 1 MiB 时保留一代轮转文件。

## Codex 联动

选择 `codex.exe` / `Codex.exe` 时会优先找到 `CODEX_HOME/sessions`；未设置环境变量时使用 `~/.codex/sessions`。联动方式应是「Codex 会话事件」，来源应是 **sessions 文件夹**。不用导出 OpenCode 插件，也不用让 Codex 额外写桌宠的 JSONL 通道。如果之前只是给 Codex 绑定了一个空的通用事件文件，需在「已绑定 Agent」中改成此方式和路径。

适配器提取 `task_started`、思考/工具类型、`task_complete`、`turn_aborted` 等本地事件，通过已有管线驱动工作动画和过程/完成气泡。中途 commentary 不代表任务结束；多个根任务尚有一个活跃时保持忙碌，子 Agent 的独立结束不触发总完成。完成气泡遵循原有 800 ms 确认，过程气泡遵循已有概率和频率限制，因此不会逐条刷屏。官方生命周期与工具类型说明见 [Codex App Server](https://developers.openai.com/codex/app-server#events)；本次直接验证了本机 Desktop 0.159.2 的持久化事件，不是连接另一个 app-server 来猜测当前任务。

本机新任务和已跟踪的会话约每 1.5 秒读取一次；所有日期目录每 30 秒刷新，恢复旧目录中的未跟踪会话最多需要约 30 秒。最多跟踪 64 个会话文件；启动前的历史不会回放，接入时已经运行的任务从后续事件开始反应。只读访问现有记录，状态簿记只保留状态/回合标识/子任务标记，气泡只使用工具类型，不转发聊天正文、代码或命令参数，也不修改 Codex 配置。临时不落盘或在其他设备执行的任务无法从这台电脑的目录获知。

## 迁移与管理

便携包包含程序与运行时，目标设备无需另装 Python。首次接入时选择当地运行的 Agent 和数据源；复制程序本身不会自动带走原电脑的绑定、模型设置或密钥。

用户目录内的绑定路径会保存为 `~/...`，插件运行时通过当前用户目录解析，适合同平台更换用户名。用户目录外的绝对路径需要在新设备上重新选择。OpenCode 分支的数据目录、事件表或插件接口有变化时，也需要重新绑定。

「已绑定 Agent」页可修改名称、来源或移除绑定；移除不会删除 Agent 的数据。启停仍可使用右键菜单中的自定义 Agent 开关。切换来源后旧来源的排队事件失效。最多保留 8 个自定义绑定。

配置字段和手动写事件的契约见 [Agent 联动协议](AGENT_LINK_PROTOCOL.md)。测试、性能与实际运行范围见 [增强版报告](PR-REPORT-running-agent-discovery-2026-10-03.md) 和 [Codex 接入修复报告](PR-REPORT-codex-link-2026-10-03.md)。
